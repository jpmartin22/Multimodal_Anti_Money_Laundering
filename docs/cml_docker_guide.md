# CML & Docker Build Guide

Covers the two automated workflows added in Phase 3 Section 2:

- **`cml.yml`** — generates model metrics reports and posts them as PR comments
- **`docker-build.yml`** — builds and pushes Docker images to GitHub Container Registry (GHCR)

---

## CML Workflow (`cml.yml`)

### What it does

On every push to `master`, pull request targeting `master`, or manual dispatch, the workflow:

1. Runs `scripts/cml_report.py` to read committed metrics JSON files
2. Generates two comparison charts (AUC-PR bar chart, multi-metric grouped bars)
3. Builds `reports/cml_report.md` which includes:
   - All-model metrics table (XGBoost baseline → GraphSAGE → BiLSTM → Late-Fusion MLP)
   - Pass/fail indicators against project targets
   - Current vs. baseline snapshot delta table (▲ / ▼ per metric)
   - GraphSAGE experiment run history
4. Posts the report as a comment on the PR using `iterative/cml@v2`
5. Uploads chart PNGs as a 30-day workflow artifact

### Triggers

| Event | Behaviour |
|-------|-----------|
| `push` → `master` | Generates report, posts comment on associated PR |
| `pull_request` → `master` | Generates report, posts comment on the PR |
| `workflow_dispatch` | Manual trigger from the Actions tab |

### Report sections

| Section | Source |
|---------|--------|
| Metrics vs targets | `graphsage_metrics.json`, `bilstm_metrics.json`, `fusion_metrics.json`, `models/baseline_metrics.json` |
| AUC-PR chart | Generated by `plot_auc_pr()` |
| Multi-metric chart | Generated by `plot_multi_metric()` |
| **Current vs. baseline delta** | Compares live metrics to `reports/baseline_snapshot.json` |
| GraphSAGE experiments | `reports/graphsage_experiment_comparison.json` |

### Updating the baseline snapshot

`reports/baseline_snapshot.json` is the committed reference for the delta table. Update it whenever a new best model is promoted:

```bash
# Edit reports/baseline_snapshot.json with the new champion metrics
# then commit on master:
git add reports/baseline_snapshot.json
git commit -m "chore(cml): advance baseline snapshot to vX.Y"
```

### Running locally

```bash
pip install matplotlib numpy pandas scikit-learn mlflow
pip install -e . --no-deps
python scripts/cml_report.py
# → reports/cml_report.md, reports/figures/cml_auc_pr.png, reports/figures/cml_metrics.png
```

### Adding a new model to the report

1. Save metrics to a JSON file (e.g. `newmodel_metrics.json`) with keys: `auc_pr`, `prec_at_recall_80`, `false_positive_rate`, `f1_fraud`
2. In `scripts/cml_report.py`:
   - Load the file in `load_metrics()`
   - Add an entry to the `data` dict (same structure as `graphsage`, `bilstm`, etc.)
   - Add the key to the `models` lists in `plot_auc_pr()`, `plot_multi_metric()`, and `build_report()`
   - Add a row in `build_delta_section()` via the `model_keys` list
3. Update `reports/baseline_snapshot.json` with an entry for the new model

## Docker Build Workflow (`docker-build.yml`)

### Images built

| Image name | Dockerfile | Purpose |
|------------|------------|---------|
| `aml-api` | `dockerfiles/Dockerfile` | FastAPI inference API (port 8000) |
| `aml-graphsage` | `dockerfiles/Dockerfile.graphsage` | GraphSAGE training (PyTorch + PyG, CPU) |
| `aml-hf` | `dockerfiles/Dockerfile.hf` | HuggingFace Spaces variant (port 7860) |

All images are pushed to **GitHub Container Registry (GHCR)**:
```
ghcr.io/<owner>/aml-api:<tag>
ghcr.io/<owner>/aml-graphsage:<tag>
ghcr.io/<owner>/aml-hf:<tag>
```

### Triggers and behaviour

| Event | Smoke-test | Push to GHCR |
|-------|-----------|-------------|
| `pull_request` → `master` | ✅ `aml-api` only | ✗ |
| `push` → `master` | ✅ | ✅ |
| `push` tag `v*.*.*` | ✅ | ✅ |
| `workflow_dispatch` (push_image=true) | ✅ | ✅ |
| `workflow_dispatch` (push_image=false) | ✅ | ✗ |

### Image tags generated

| Rule | Example |
|------|---------|
| Branch name | `master` |
| Semantic version (full) | `1.2.3` |
| Semantic version (minor) | `1.2` |
| Short SHA | `sha-abc1234` |
| Latest (default branch only) | `latest` |
| PR reference | `pr-42` |

### Authentication

The workflow uses the built-in `GITHUB_TOKEN` secret — no manual setup required. The token is granted `packages: write` permission within the job.

To pull a pushed image:

```bash
docker pull ghcr.io/<owner>/aml-api:latest
```

### Layer caching

Each image uses a separate GitHub Actions cache scope (`scope=aml-api`, `scope=aml-graphsage`, `scope=aml-hf`). This avoids cache collisions and keeps incremental rebuilds fast.

### Releasing a new version

```bash
git tag v1.2.0
git push origin v1.2.0
# Triggers docker-build.yml → pushes ghcr.io/<owner>/aml-api:1.2.0 and :1.2
```

### Adding a new image

1. Create `dockerfiles/Dockerfile.<name>`
2. Add a matrix entry in `.github/workflows/docker-build.yml`:

```yaml
- image: aml-<name>
  dockerfile: dockerfiles/Dockerfile.<name>
  description: "One-line description"
```

That's all — the rest of the workflow handles login, tagging, caching, and the job summary automatically.

### Switching registry (e.g. Docker Hub)

Replace the `REGISTRY` env var and the `docker/login-action` credentials:

```yaml
env:
  REGISTRY: docker.io

- name: Log in to Docker Hub
  uses: docker/login-action@v3
  with:
    username: ${{ secrets.DOCKERHUB_USERNAME }}
    password: ${{ secrets.DOCKERHUB_TOKEN }}
```

Update the `images:` field in `docker/metadata-action` to `docker.io/<org>/${{ matrix.image }}`.
